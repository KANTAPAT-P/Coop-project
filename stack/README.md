# stack — ระบบรับส่งและจัดเก็บข้อมูล

ไฟล์ Docker Compose ไฟล์เดียวรันครบทั้งระบบ ใช้ได้ทั้งบนโน้ตบุ๊ก Windows
และ Raspberry Pi 5 เพราะอิมเมจทั้งสามตัวมีรุ่น arm64 ครบ

การออกแบบและเหตุผลอยู่ใน `docs/data-pipeline-design.md`
ผลการทดสอบอยู่ใน `experiments/2026-09-28-pipeline-end-to-end.md`

## ครั้งแรก

```bash
cp stack/.env.example stack/.env
```

แล้ว**แก้ทุกบรรทัดใน `stack/.env`** โดยเฉพาะรหัสผ่านและ token
ไฟล์นี้ไม่ขึ้น git ตอนย้ายไป Raspberry Pi ต้องสร้างใหม่ที่เครื่องนั้น

## คำสั่งที่ใช้บ่อย

```bash
# ยกขึ้น
docker compose -f stack/docker-compose.yml --env-file stack/.env up -d

# ดูสถานะ
docker compose -f stack/docker-compose.yml --env-file stack/.env ps

# ดู log
docker compose -f stack/docker-compose.yml --env-file stack/.env logs -f mosquitto

# หยุด (ข้อมูลยังอยู่)
docker compose -f stack/docker-compose.yml --env-file stack/.env down

# หยุดและลบข้อมูลทิ้งทั้งหมด
docker compose -f stack/docker-compose.yml --env-file stack/.env down -v
```

## บริการและพอร์ต

| บริการ | พอร์ต | เข้าถึง |
|---|---|---|
| Mosquitto | 1883 | MQTT broker |
| InfluxDB 2 | 8086 | http://localhost:8086 |
| Grafana | 3000 | http://localhost:3000 |

เข้า InfluxDB และ Grafana ด้วยชื่อผู้ใช้และรหัสผ่านที่ตั้งไว้ใน `.env`

## ทดสอบว่าระบบทำงาน

เปิดสองหน้าต่าง

```bash
# หน้าต่างที่ 1 — ตัวรับข้อมูล ประเมิน และส่งผลเข้า topic assessment
python src/service/ingest.py --seconds 180

# หน้าต่างที่ 2 — ตัวจำลองอุปกรณ์ เล่นข้อมูลจริงจาก MAFAULDA
python src/service/simulate.py --backfill-hours 2 --limit 10 --interval 0.5
```

> ⚠️ **ต้องมีไฟล์โมเดลก่อน** `ingest.py` จะโหลด `models/baseline-normal.json`
> ถ้าไม่มีจะยังรับข้อมูลได้แต่**ไม่ประเมินอะไรเลย** พร้อมพิมพ์เตือนไว้
> สร้างด้วย `python src/models/eval_detector.py` (ใช้เวลาราวหนึ่งนาที)
> หรือสั่ง `--no-model` ถ้าตั้งใจจะรับข้อมูลอย่างเดียว

ผลที่ควรได้คือ **จำนวนที่ส่งเท่ากับจำนวนที่ broker ตอบรับ และเท่ากับจำนวนที่
ผู้รับได้รับ** ถ้าไม่เท่ากันแปลว่ามีข้อความหาย ดูสาเหตุที่เป็นไปได้ในบันทึก
การทดลองวันที่ 2026-09-28

ดูรูปแบบข้อความโดยไม่ต้องยก stack ขึ้น

```bash
python src/service/simulate.py --dry-run --limit 1
```

**ตรวจตรรกะการตัดสิน 15 ข้อโดยไม่ต้องมี broker หรือฐานข้อมูล** รันไม่ถึงวินาที
จึงรันได้ทุกครั้งที่แก้โค้ด

```bash
python src/service/check_evaluate.py
```

### ผลการประเมินไปสองที่

| ปลายทาง | ใครใช้ |
|---|---|
| topic `pdm/<site>/<area>/<machine>/assessment` | ระบบอื่นที่สมัครรับ โดยไม่ต้องต่อฐานข้อมูล |
| measurement `assessment` ใน InfluxDB | **Grafana** ซึ่งอ่านจากฐานข้อมูล ไม่ได้อ่านจาก MQTT |

**ต้องเขียนทั้งสองที่** ถ้าส่งแต่ MQTT ผลการประเมินจะไม่มีทางขึ้นแดชบอร์ดได้เลย
ซึ่งเป็นบั๊กที่เจอจริงตอนทดสอบรอบแรก ดูบันทึกวันที่ 2026-10-04

**ส่งทุกข้อความ ไม่ใช่เฉพาะตอนผิดปกติ** เพราะผู้รับต้องแยกออกได้ระหว่าง
"ประเมินแล้วปกติ" กับ "ไม่มีใครประเมินอยู่" ถ้าส่งเฉพาะตอนผิดปกติ ความเงียบจะกำกวม

## แดชบอร์ด

Grafana ตั้งค่า**แหล่งข้อมูลและแดชบอร์ดให้อัตโนมัติ**ตอนคอนเทนเนอร์ขึ้น
จากไฟล์ใน `stack/grafana/` ไม่ต้องกดสร้างในหน้าเว็บ

เข้าที่ http://localhost:3000 แล้วเปิดโฟลเดอร์ **Predictive Maintenance**
จะเจอแดชบอร์ด **ภาพรวมสภาพเครื่องจักร** ซึ่งมี **13 แผง**

**แผงบนสุดคือตารางบอกว่าเครื่องจำลองตัวไหนคือคลาสอะไร** อ่านจาก `MACHINES`
ใน `simulate.py` โดยตรง จึงตรงกับของจริงเสมอ

### กลุ่มที่ 1 — ค่าดิบ (7 แผง)

| แผง | แสดงอะไร |
|---|---|
| สถานะการวัดความเร็วรอบล่าสุด | ความเร็วล่าสุดของทุกเครื่อง |
| อุณหภูมิล่าสุด | (ค่าสังเคราะห์จากสคริปต์จำลอง) |
| ความเร็วรอบ | **ต้องดูคู่กับแผงความแรงเสมอ** |
| ความแรงการสั่น `u_radial.rms` | ตัวชี้วัดตระกูลความแรง |
| ลายเซ็น imbalance `u_radial.h1_frac` | motor-02 ควรสูงกว่าเพื่อนชัดเจน |
| ลายเซ็น misalignment `o_tang.r21` | motor-03 และ motor-04 |
| คุณภาพการวัดความเร็วรอบ | แถบเวลาแสดง ok / noisy / lost / stopped |

### กลุ่มที่ 2 — ผลการประเมิน (4 แผง)

เพิ่มเมื่อ 2026-10-04 **เดิมแดชบอร์ดมีแต่ค่าดิบ คนดูต้องตีความเองว่าผิดปกติหรือยัง
ซึ่งเป็นงานของระบบ**

| แผง | แสดงอะไร |
|---|---|
| **คะแนนความผิดปกติ เทียบกับเกณฑ์** | จำนวนตัวชี้วัดที่หลุดเส้นฐาน จาก 72 ตัว **มีเส้นแดงเป็นเกณฑ์บนกราฟ** |
| สถานะล่าสุดของแต่ละเครื่อง | 1 = ผิดปกติ · 0 = อยู่ในเกณฑ์ · ว่าง = **ไม่มีใครส่งข้อมูล ซึ่งต่างจากปกติ** |
| จำนวนข้อความที่ผิดปกติ รวมรายชั่วโมง | ใช้ดู**ทิศทาง** ว่าแย่ลงเรื่อยๆ หรือกระจัดกระจาย |
| ค่าสถิติแนวโน้ม Mann-Kendall (tau) | ค่าบวกมาก = แย่ลงเรื่อยๆ · ใกล้ศูนย์ = ไม่มีทิศทาง |

⚠️ **สองแผงสุดท้ายต้องมีข้อมูลอย่างน้อย 4 วันจึงจะมีค่า** ถ้าเพิ่งเริ่มเก็บจะว่าง
ซึ่งไม่ใช่ความผิดพลาด ใช้ `simulate.py --backfill-hours` เติมย้อนหลังได้

**แก้แดชบอร์ด** ให้แก้สคริปต์แล้วสร้างไฟล์ใหม่ ไม่ควรแก้ในหน้าเว็บ
เพราะการแก้ในหน้าเว็บจะหายเมื่อ provisioning โหลดไฟล์ทับ

```bash
python stack/grafana/make_dashboard.py
```

Grafana โหลดไฟล์ใหม่เองทุก 30 วินาที ไม่ต้องรีสตาร์ทคอนเทนเนอร์

## ⚠️ ข้อควรระวัง

- 🚨 **ข้อมูลบนแดชบอร์ดไม่ใช่ข้อมูลของเครื่องจักรจริง** สคริปต์จำลองหยิบบรรทัด
  จากตาราง feature มาส่งซ้ำ โดยให้ความเร็วรอบแกว่งตาม**คลื่นไซน์ที่เขียนไว้
  ในโค้ด** เส้นกราฟที่ขึ้นลงจึงเป็นของคลื่นนั้น ไม่ใช่แนวโน้มการเสื่อมสภาพ
  และค่าอุณหภูมิกับโหลดเป็นค่าที่สร้างขึ้นทั้งหมด เพราะ MAFAULDA ไม่มีสองอย่างนี้
  รายละเอียดอยู่ใน docstring ของ `src/service/simulate.py`
- 🚨 **ต้องเล่นตารางที่ตรงกับหน้าต่างที่โมเดลเทรน** ไม่งั้น `ingest.py`
  จะตอบ `indeterminate` ทุกข้อความ ซึ่งเป็นพฤติกรรมที่ถูกต้องแต่ไม่มีอะไรขึ้นจอ

  ```bash
  python src/service/simulate.py --grid data/processed/feature_grid_win410ms.csv
  ```

  โมเดลปัจจุบันเทรนด้วย**หน้าต่างที่เทรน 410 ms** ดูฟิลด์ `window` ใน
  `models/baseline-normal.json` สร้างตารางด้วย
  `python src/features/feature_grid.py --window-ms 409.6`
- **การตั้งค่าปัจจุบันเปิดให้เชื่อมต่อ MQTT โดยไม่ต้องยืนยันตัวตน**
  ใช้ได้เฉพาะในเครือข่ายภายในตอนพัฒนา ก่อนขึ้นระบบจริงต้องตั้ง
  `allow_anonymous false` พร้อมไฟล์รหัสผ่าน และพิจารณาเปิด TLS
- `down -v` **ลบข้อมูลในฐานข้อมูลทิ้งทั้งหมด** ใช้เฉพาะตอนต้องการเริ่มใหม่
- **รหัสผ่าน Grafana อยู่ใน `.env` ไม่ใช่ `admin:admin`** ถ้าลองผิดหลายครั้งติดกัน
  Grafana จะบล็อกการล็อกอินชั่วคราว 5–10 นาทีตามกลไกป้องกัน brute-force
  **หายเอง ไม่ต้องแก้อะไร**
- ⬜ **ตอนนี้มี bucket เดียวคือ `pdm_live` ที่เก็บ 14 วัน** แปลว่า
  **ข้อมูลทุกอย่างหายหลัง 14 วัน รวมถึงประวัติการแจ้งเตือนด้วย**
  ยอมรับได้ระหว่างพัฒนา แต่ต้องเพิ่ม `pdm_events` ก่อนขึ้นระบบจริง
- บน Raspberry Pi ให้ระวังเรื่องการเขียนลง microSD ดู
  `docs/data-pipeline-design.md` §5.5

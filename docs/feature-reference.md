## 1. ขั้นตอนก่อนคำนวณ: กรองความถี่ต่ำกว่า 10 Hz ทิ้ง

ทุก feature คำนวณหลังผ่าน high-pass filter (Butterworth อันดับ 4 ที่ 10 Hz) แล้ว

เหตุผลคือช่องเซ็นเซอร์ `o_axial` มี **drift** คือเส้นฐานค่อยๆ ลอยขึ้นลงอย่างช้ามาก
ซึ่งกินพลังงานถึง 64% ของสัญญาณโดยไม่ได้เป็นการสั่นของเครื่องจักรจริง ถ้าไม่กรองทิ้งก่อน
feature เกือบทุกตัวจะถูกความเคลื่อนไหวนั้นครอบงำจนอ่านอะไรไม่ได้

> ⚠️ **ข้อจำกัดที่ตามมา** ที่ความเร็วรอบต่ำกว่าราว 15 Hz พีคที่ความเร็วรอบ (1×) เริ่มเข้าใกล้
> ความถี่ตัดของฟิลเตอร์ และถูกกรองกินไปบางส่วน ค่า `h1_frac` และ `r21` ที่ความเร็วต่ำมาก
> จึงต่ำกว่าความจริงเล็กน้อย การคัดกรองลายเซ็นทั้งหมดในโปรเจกต์นี้จึงทำในช่วง **20–42 Hz**

## 2. กลุ่มที่ 1 — feature จากรูปคลื่นโดยตรง (time domain)

คำนวณจากตัวเลขในโดเมนเวลาตรงๆ ไม่ต้องทำ FFT จึงเร็วที่สุดและเบาที่สุด

### 2.1 `p2p` — ความสูงยอดถึงยอด (peak-to-peak)

```
p2p = ค่าสูงสุด − ค่าต่ำสุด
```

คือความสูงของกราฟสัญญาณดิบตรงๆ ในโปรเจกต์นี้คิดเป็น**มัธยฐานของ p2p รายหน้าต่าง 67 ms**
ตลอดทั้งไฟล์ (72 หน้าต่าง) ไม่ใช่ `max − min` ของทั้งไฟล์ เพราะค่าหลังถูกกำหนดโดย
สไปก์เดียวที่แรงที่สุด ซึ่งอาจเป็นสัญญาณรบกวนชั่วขณะ ไม่ใช่ลักษณะของความเสียหาย

### 2.2 `rms` — ความแรงเฉลี่ย (root mean square)

```
rms = √( ค่าเฉลี่ยของ x² )
```

**ทำไมต้องยกกำลังสองก่อน** การสั่นมีค่าทั้งบวกและลบสลับกัน ถ้าหาค่าเฉลี่ยตรงๆ
จะหักล้างกันจนได้ศูนย์เสมอไม่ว่าเครื่องจะสั่นแรงแค่ไหน การยกกำลังสองทำให้เป็นบวกทั้งหมด
หาค่าเฉลี่ย แล้วถอดรากที่สองกลับเพื่อให้หน่วยเป็น g เหมือนสัญญาณเดิม

`rms` ต่างจาก `p2p` ตรงที่ `p2p` สนใจเฉพาะจุดสูงสุดและต่ำสุด ส่วน `rms` คิดจากทุกจุด
จึงทนต่อสไปก์เดี่ยวๆ มากกว่า และเป็นตัวแทนของ**พลังงานการสั่นรวม**

### 2.3 `crest` — crest factor

```
crest = ค่าสัมบูรณ์สูงสุด / rms
```

บอกว่ายอดที่สูงที่สุดสูงกว่าระดับปกติของสัญญาณกี่เท่า คลื่นไซน์บริสุทธิ์ได้ **1.41** (= √2)
เพราะยอดของไซน์สูงกว่า rms ของตัวมันเองเท่ากับ √2 พอดี สัญญาณที่มีการกระแทกแหลมๆ
จะได้ค่าสูงกว่านั้นมาก

### 2.4 `kurt` — kurtosis ของสัญญาณดิบ

```
kurt = ค่าเฉลี่ยของ ( (x − ค่าเฉลี่ย) / ส่วนเบี่ยงเบนมาตรฐาน )⁴
```

เป็นตัววัดทางสถิติที่ตอบคำถามว่า **"สัญญาณนี้ประกอบด้วยเหตุการณ์หายากที่รุนแรงมากแค่ไหน"**

หัวใจอยู่ที่**เลขยกกำลังสี่** ซึ่งทำให้จุดที่อยู่ไกลจากค่ากลางมีน้ำหนักมหาศาล
จุดที่ห่างจากค่ากลาง 3 เท่าของส่วนเบี่ยงเบนมาตรฐานได้น้ำหนัก 3⁴ = **81**
ขณะที่จุดที่ห่าง 1 เท่าได้น้ำหนักเพียง **1** ผลคือ kurtosis แทบไม่สนใจสัญญาณส่วนใหญ่เลย
มันวัดเฉพาะว่ามี**ค่าสุดโต่ง**อยู่มากน้อยเพียงใด

**ค่าหลักไมล์ที่ควรจำ** (วัดจากสัญญาณสังเคราะห์ 200,000 จุด)

| สัญญาณ | `kurt` | `crest` |
|---|---:|---:|
| คลื่นไซน์บริสุทธิ์ | **1.50** | 1.41 |
| Gaussian noise (สุ่มล้วน) | **3.01** | 4.73 |
| Gaussian noise + การกระแทกเป็นระยะ | **63.85** | 25.09 |

**ทำไมคลื่นไซน์จึงได้ค่าต่ำกว่าสัญญาณสุ่ม** เพราะคลื่นไซน์ไม่มีค่าสุดโต่งเลย
มันวิ่งอยู่ระหว่าง −1 ถึง +1 เท่านั้นและใช้เวลาอยู่ใกล้ยอดมากกว่าใกล้ศูนย์
(เพราะตอนเข้าใกล้ยอดความเร็วลดลง) การกระจายของมันจึงแบนราบและไม่มีหาง

> 🚨 **กับดักเรื่องนิยาม** ตำราสถิติจำนวนมากรายงาน *excess kurtosis* ซึ่งลบ 3 ออกไปแล้ว
> ทำให้ Gaussian ได้ **0** โปรเจกต์นี้ใช้ค่าดิบ (`scipy.stats.kurtosis(..., fisher=False)`)
> ซึ่ง **Gaussian ได้ 3** ถ้านำตัวเลขไปเทียบกับเอกสารอื่นต้องตรวจก่อนว่าเป็นนิยามใด

## 3. กลุ่มที่ 2 — feature จากสเปกตรัม (frequency domain)

คำนวณหลังทำ FFT (ใช้หน้าต่าง Hann พร้อมชดเชย coherent gain) สเปกตรัมบอกว่าพลังงาน
การสั่นกระจายอยู่ที่ความถี่ใดบ้าง

### 3.1 `h1_frac` — สัดส่วนพลังงานที่ความเร็วรอบ

```
h1_frac = ( แอมพลิจูดพีคที่ 1× ÷ √2 )² / rms²
```

`a/√2` คือค่า rms ของคลื่นไซน์ที่มีแอมพลิจูด `a` เมื่อยกกำลังสองจึงได้พลังงานของ
องค์ประกอบที่ 1× และเมื่อหารด้วย `rms²` ซึ่งเป็นพลังงานรวม ผลลัพธ์จึงเป็น**สัดส่วน
ระหว่าง 0 ถึง 1** ที่ตีความได้ทันทีว่า "พลังงานกี่เปอร์เซ็นต์อยู่ที่ความเร็วรอบ"

ตรวจสอบสูตรกับคลื่นไซน์บริสุทธิ์แล้วได้ **0.956** (ค่าในอุดมคติคือ 1.000)
ส่วนที่ขาดไป 4% เกิดจาก spectral leakage ของหน้าต่าง Hann เมื่อความถี่ของสัญญาณ
ไม่ตกลงบนช่องความถี่พอดี ซึ่งเป็นข้อจำกัดเชิงระบบที่มีผลเท่ากันทุกไฟล์

**นี่คือลายเซ็นของ imbalance โดยตรง** มวลที่ไม่สมดุลหมุนครบรอบหนึ่งครั้งต่อการหมุน
หนึ่งรอบพอดี จึงสร้างแรงเป็นคลื่นไซน์ที่ความถี่ 1× เท่านั้น

### 3.2 `r21` — อัตราส่วนพีคที่ 2× ต่อพีคที่ 1×

```
r21 = ความสูงพีคที่ 2× ของความเร็วรอบ / ความสูงพีคที่ 1×
```

**ไม่เกี่ยวกับความแรงของการสั่นเลย** เป็นตัววัด "รูปร่าง" ว่าพลังงานกระจายอย่างไร
ระหว่างสองความถี่นี้ ค่านี้ไม่เปลี่ยนแม้เซ็นเซอร์จะมีความไวต่างกัน

**นี่คือลายเซ็นของ misalignment** เพลาที่เยื้องศูนย์ทำให้คัปปลิ้งถูกบีบและคลาย
**สองครั้งต่อการหมุนหนึ่งรอบ** ไม่ใช่ครั้งเดียวแบบ imbalance พลังงานจึงย้ายจาก 1× ไป 2×
โดยที่**ความแรงรวมอาจเท่าเดิมทุกประการ**

> ข้อสังเกตเชิงปฏิบัติ: imbalance และ misalignment ดันค่านี้ไปคนละทิศ
> imbalance ทำให้ลดลง (เพราะ 1× พุ่งขึ้น) ส่วน misalignment ทำให้เพิ่มขึ้น
> จึงแยกสองความผิดปกตินี้ออกจากกันได้ด้วย feature ตัวเดียว

### 3.3 `e_low` / `e_mid` / `e_high` — รูปร่างของสเปกตรัม

```
e_low  = พลังงานช่วง 5 Hz ถึง 10× ความเร็วรอบ ÷ พลังงานรวม
e_mid  = พลังงานช่วง 10× ความเร็วรอบ ถึง 2 kHz ÷ พลังงานรวม
e_high = พลังงานช่วง 2 kHz ถึง 10 kHz ÷ พลังงานรวม
```

สามค่ารวมกันได้ประมาณ 1.0 บอกว่าพลังงานกระจายอยู่ในย่านความถี่ใด

- `e_low` คือย่านของความไม่สมดุลและการเยื้องศูนย์ ซึ่งเป็นแรงระดับรอบการหมุน
- `e_high` คือย่านที่โครงสร้างของเครื่องสั่นตอบสนองเมื่อถูกกระแทก จึงเป็นย่านของตลับลูกปืน

> ⚠️ **กับดัก** เส้นแบ่งระหว่าง `e_low` กับ `e_mid` คือ **10 เท่าของความเร็วรอบ
> ซึ่งขยับตามความเร็ว** ที่ 13 Hz เส้นอยู่ที่ 130 Hz แต่ที่ 62 Hz เส้นอยู่ที่ 620 Hz
> เวลาเปรียบเทียบค่าข้ามความเร็วรอบต้องระลึกว่ากรอบที่ใช้วัดก็เลื่อนไปด้วย

## 4. กลุ่มที่ 3 — feature จาก envelope (จังหวะการกระแทก)

**หลักการที่ต้องเข้าใจก่อน** รอยแตกเล็กๆ ในตลับลูกปืนไม่ได้ทำให้เกิดการสั่นที่ความถี่
ความเสียหาย (BPFO/BSF/FTF) โดยตรง มันเพียงแต่**กระแทก**ทุกครั้งที่ลูกปืนกลิ้งผ่านรอย
แล้วแรงกระแทกนั้นไปกระตุ้นความถี่ธรรมชาติของโครงสร้างที่ 2–5 kHz ให้สั่นแล้วค่อยๆ ซาลง

สิ่งที่เซ็นเซอร์บันทึกได้จึงเป็นคลื่นความถี่สูง 2–5 kHz ที่ดังและเบาสลับกันตามจังหวะ
การกระแทกที่ช้ากว่ามาก **envelope คือเส้นขอบบนของคลื่นนั้น** ซึ่งเก็บเฉพาะจังหวะเอาไว้
กระบวนการมีสามขั้น: bandpass 2–5 kHz → Hilbert transform → FFT ของ envelope

### 4.1 `kurt_band` — kurtosis หลัง bandpass 2–5 kHz

kurtosis ตัวเดียวกับหัวข้อ 2.4 แต่คำนวณหลังกรองให้เหลือเฉพาะย่าน 2–5 kHz แล้ว
การกรองตัดคลื่นไซน์ย่านความถี่ต่ำทิ้งไปก่อน ค่าที่ได้จึงวัด**ความแหลมของการกระแทก**
ล้วนๆ โดยไม่ถูกรบกวนจากความไม่สมดุล

### 4.2 `env_floor` — ระดับพื้นของ envelope spectrum

```
env_floor = มัธยฐานของ envelope spectrum ในช่วง 2–250 Hz
```

**ทำไมใช้มัธยฐานไม่ใช่ค่าเฉลี่ย** เพราะสิ่งที่ต้องการวัดคือ "ระดับพื้น" ไม่ใช่ความสูงของพีค
มัธยฐานไม่ถูกดึงโดยค่าสูงสุดไม่กี่ค่า จึงสะท้อนปริมาณ**การกระแทกแบบสุ่มที่กระจายอยู่ทั่วไป**
ซึ่งเป็นลักษณะของพื้นผิวที่เสียหาย

### 4.3 `env_rel` — env_floor ที่หักล้างความไวของเซ็นเซอร์แล้ว

```
env_rel = env_floor / rms ของสัญญาณหลัง bandpass 2–5 kHz
```

**จุดประสงค์เดียวคือทำให้ค่าไม่ขึ้นกับความไวของเซ็นเซอร์** ถ้าเซ็นเซอร์ถูกขันแน่นกว่า
หรือมี gain สูงกว่า ทั้งตัวเศษและตัวส่วนจะเพิ่มขึ้นในสัดส่วนเดียวกัน อัตราส่วนจึงไม่เปลี่ยน

ข้อนี้สำคัญเป็นพิเศษกับชุดข้อมูลนี้ เพราะความเสียหายแต่ละแบบต้องถอดประกอบเครื่องใหม่
เพื่อเปลี่ยนตลับลูกปืนหรือเลื่อนฐานมอเตอร์ จึงมีความเป็นไปได้สูงที่การติดตั้งเซ็นเซอร์
จะไม่เหมือนกันทุกครั้ง

## 5. ค่าอ้างอิงจากข้อมูลจริง

วัดจากช่อง `u_radial` ที่ความเร็วรอบประมาณ 30 Hz **หนึ่งไฟล์ต่อหนึ่งแถว**

| ไฟล์ | `rms` | `kurt` | `crest` | `h1_frac` | `r21` | `e_high` | `env_rel` |
|---|---:|---:|---:|---:|---:|---:|---:|
| **normal** | 0.369 | 2.85 | 5.36 | 0.089 | 0.16 | 0.093 | 0.0134 |
| imbalance 35 g | 0.809 | **2.31** | **4.28** | **0.652** | 0.01 | 0.013 | 0.0146 |
| underhang ball fault 0 g | 1.166 | 2.96 | 4.54 | 0.010 | 0.13 | 0.081 | 0.0163 |
| horizontal misalign 2.0 mm | 0.401 | 2.54 | 4.75 | 0.073 | **0.30** | 0.411 | 0.0154 |

**สิ่งที่ตารางนี้แสดง**

- **imbalance** ทำให้ `h1_frac` เพิ่มจาก 0.089 เป็น **0.652** แปลว่าพลังงานกว่า 65%
  ไปรวมอยู่ที่ความถี่เดียวคือความเร็วรอบ ซึ่งตรงกับทฤษฎีทุกประการ
- **horizontal misalignment** ทำให้ `r21` เพิ่มจาก 0.16 เป็น 0.30 ขณะที่ `rms`
  แทบไม่เปลี่ยน (0.369 → 0.401) ยืนยันว่าเป็นการย้ายพลังงาน ไม่ใช่การสั่นแรงขึ้น

> 🚨 **กับดักที่สำคัญที่สุดในตารางนี้** imbalance 35 g ทำให้ `kurt` **ลดลง**
> จาก 2.85 เหลือ 2.31 และ `crest` ลดลงจาก 5.36 เหลือ 4.28 ทั้งที่เป็นความผิดปกติชัดเจน
>
> สาเหตุคือ imbalance สร้างคลื่นไซน์ขนาดใหญ่ ซึ่งมี kurtosis เพียง 1.5 จึงดึงค่าของ
> สัญญาณรวมลงต่ำ **ถ้าใช้ kurtosis เป็นตัวชี้วัดความผิดปกติเพียงตัวเดียว จะตรวจไม่พบ
> ความไม่สมดุลระดับ 35 กรัมเลย** ซึ่งขัดกับสามัญสำนึกและขัดกับคำแนะนำในตำราทั่วไป

## 6. กับดักที่ต้องระวังเมื่อนำ feature เหล่านี้ไปใช้

| # | กับดัก | ผลที่เกิดขึ้น |
|---|---|---|
| 1 | **`kurt` และ `crest` ลดลงเมื่อเจอ imbalance** | ตรวจไม่พบความไม่สมดุล ดูหัวข้อ 5 |
| 2 | **`kurt` และ `crest` ตกกลับลงเมื่อความเสียหายลุกลาม** | ตอนเริ่มมีรอยแตก การกระแทกเป็นสไปก์ห่างๆ ค่าจึงพุ่งขึ้น แต่เมื่อรอยแตกขยายจนกระแทกถี่ตลอดเวลา สัญญาณกลับไปคล้าย random noise ค่าจึง**ตกกลับลงมาทั้งที่สภาพจริงแย่ลง** ห้ามใช้ตัวเดียวโดดๆ ต้องดูคู่กับ `rms` ที่เพิ่มขึ้นเรื่อยๆ |
| 3 | **นิยาม kurtosis มีสองแบบ** | ของโปรเจกต์นี้ Gaussian = 3 ส่วนตำราจำนวนมากใช้ excess kurtosis ที่ Gaussian = 0 |
| 4 | **เส้นแบ่ง `e_low`/`e_mid` ขยับตามความเร็วรอบ** | เปรียบเทียบข้ามความเร็วต้องระวัง |
| 5 | **`rms`, `p2p`, `env_floor` ขึ้นกับความไวของเซ็นเซอร์** | ถ้าการติดตั้งเซ็นเซอร์ต่างกันระหว่างรอบบันทึก ค่าจะเพี้ยนตามโดยไม่เกี่ยวกับความเสียหาย |
| 6 | **ต่ำกว่า 15 Hz ฟิลเตอร์ 10 Hz เริ่มกินพีค 1×** | `h1_frac` และ `r21` ต่ำกว่าความจริง |
| 7 | **ห้ามใช้ความสูงของพีคที่ BPFO/BSF/FTF เป็นหลักฐาน** | ตรวจไฟล์ `ball_fault` ที่ 0 g ครบทั้ง 51 ไฟล์แล้ว **ไม่มีไฟล์ใดเลย**ที่พีคเด่นที่สุดใน envelope spectrum ตกที่ความถี่ความเสียหาย ทุกไฟล์เป็นฮาร์มอนิกของความเร็วรอบ |

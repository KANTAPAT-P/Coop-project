# refractory period สร้างสัญญาณปลอมที่ผ่านเกณฑ์คุณภาพได้ทุกข้อ

วันที่ 2026-10-13

## ที่มา

คำถามคือ **ถ้าไม่ทราบหน่วยของช่อง `tach` จะคำนวณความเร็วรอบได้อย่างไร**
ซึ่งเป็นคำถามที่ถูก เพราะ `tachometer.py` มี `DEFAULT_THRESHOLD = 2.5`
ซึ่งเป็น**ค่าสัมบูรณ์** ที่ผูกกับสเกลของชุดข้อมูลนี้

ระหว่างตรวจเรื่องนั้นพบปัญหาที่ร้ายแรงกว่า

## คำตอบของคำถามเดิม — หน่วยไม่เข้าสมการ แต่ threshold เข้า

ความเร็วรอบคำนวณจาก

```
rot_hz = fs × จำนวนรอบ / จำนวนตัวอย่างระหว่างขอบแรกกับขอบสุดท้าย
```

ทุกตัวเป็นจำนวนนับหรือเวลา **แอมพลิจูดไม่ปรากฏในสมการเลย**
ผลลัพธ์จึงอยู่ในหน่วย Hz ไม่ว่าสัญญาณเข้าจะอยู่ในหน่วยใด

ทดสอบโดยคูณช่อง `tach` ด้วยค่าคงที่ ซึ่งเทียบเท่ากับการเปลี่ยนหน่วย

| ไฟล์ | ชื่อไฟล์ (Hz) | ตัวคูณ | `threshold=2.5` | `threshold=None` |
|---|---:|---:|---:|---:|
| `12.288.csv` | 12.2880 | ×1 | 12.3762 | 12.3762 |
| | | ×10 | 12.3762 | 12.3762 |
| | | **×0.1** | **nan** | **12.3762** |
| | | ×1000 | 12.3762 | 12.3762 |
| `36.4544.csv` | 36.4544 | ×1 | 36.4035 | 36.4035 |
| | | ×0.1 | **nan** | 36.4035 |
| `61.44.csv` | 61.4400 | ×1 | 61.4801 | 61.4801 |
| | | ×0.1 | **nan** | 61.4801 |

**โหมดที่คำนวณ threshold จากสัญญาณเองให้ค่าเท่ากันทุกทศนิยมในช่วงสเกล
10,000 เท่า** ส่วนค่าคงที่ 2.5 พังเมื่อสัญญาณเล็กลงสิบเท่า เพราะทั้งเส้น
ตกต่ำกว่า threshold จึงไม่มีขอบให้นับ

เทียบสองโหมดกับไฟล์ `normal` ครบ 49 ไฟล์

| โหมด | อัตราส่วนต่อชื่อไฟล์ | ผ่าน ±1% |
|---|---|---:|
| `threshold = 2.5` | 0.99704 – 1.00738 มัธยฐาน 1.00062 | 49 / 49 |
| `threshold = None` | 0.99703 – 1.00738 มัธยฐาน 1.00062 | 49 / 49 |

ต่างกันสูงสุด **2.24 × 10⁻⁴ Hz** จึงเท่ากันในทางปฏิบัติ

## 🚨 ปัญหาที่พบระหว่างทาง — สัญญาณรบกวนล้วนผ่านเกณฑ์คุณภาพทุกข้อ

เมื่อทดสอบว่าโหมด `threshold=None` ปลอดภัยหรือไม่ จึงป้อนสัญญาณที่
**ไม่มีพัลส์เลย** เข้าไป

| สัญญาณเข้า | `threshold=2.5` | `threshold=None` |
|---|---:|---:|
| สัญญาณรบกวนล้วน (เครื่องหยุด) | nan ✅ | **69.704** ❌ |
| ศูนย์ทั้งเส้น (สายหลุด) | nan ✅ | nan ✅ |
| ไฟตรงค้างที่ 3 V | nan ✅ | nan ✅ |
| `tach` จริง หาร 10 | **nan** ❌ | 12.376 ✅ |

ค่า 69.704 Hz ไม่ใช่เลขสุ่ม **มันคือเพดานของ refractory period
ที่ตั้งไว้ 70 Hz พอดี**

และที่ร้ายแรงกว่าคือ

```
สัญญาณรบกวนล้วน   rot_hz = 69.704   jitter = 0.317%   is_trustworthy = True
tach จริง 12.3 Hz  rot_hz = 12.376   jitter = 0.322%   is_trustworthy = True
```

**สัญญาณรบกวนได้ jitter ดีกว่าสัญญาณจริง**

### กลไก

`refractory period` ถูกใส่เข้ามาเพื่อแก้กับดักที่ 2 ของ tachometer
คือพัลส์หยักกลางพัลส์แล้วถูกนับซ้ำ มันทิ้งขอบที่อยู่ใกล้ขอบก่อนหน้า
เกินกว่าจะเป็นรอบถัดไปได้จริง

สัญญาณรบกวนข้าม threshold ตลอดเวลา **ขอบทุกอันจึงถูกดันไปอยู่ที่ระยะ
ขั้นต่ำพอดีทุกอัน** ผลคือช่วงห่างสม่ำเสมอที่สุดเท่าที่เป็นไปได้
jitter จึงเกือบศูนย์

> **กลไกที่ใส่ไว้กันความผิดพลาดหนึ่ง สร้างความผิดพลาดอีกแบบขึ้นมา
> และแบบใหม่มองเห็นยากกว่า เพราะมันผ่านทุกเกณฑ์ที่เรามีอยู่**

### ทำไมข้อนี้ร้ายแรง

`CLAUDE.md` ระบุไว้เองว่า **เมื่อปรับมาตรฐานด้วยตัวแปรใด ความน่าเชื่อถือ
ของตัวแปรนั้นคุมทั้งระบบ** เส้นฐานของตัวชี้วัดทั้ง 72 ตัวเป็นฟังก์ชันของ
`rot_hz` ถ้า `rot_hz` เป็นค่าที่แต่งขึ้นมาจากสัญญาณรบกวนโดยที่ระบบคิดว่า
เชื่อถือได้ **ระบบจะประเมินต่อไปแทนที่จะตอบ `indeterminate`**

## วิธีแก้ — ใช้ `duty_pct` ซึ่งเป็นปริมาณเชิงฟิสิกส์

ค่าที่แยกสองกรณีออกจากกันได้อยู่ใน `TachResult` อยู่แล้ว เพียงแต่
`is_trustworthy` ไม่ได้ดู

| สัญญาณ | `rot_hz` | พัลส์ | `jitter_pct` | **`duty_pct`** |
|---|---:|---:|---:|---:|
| สัญญาณรบกวนล้วน | 69.70 | 341 | 0.317 | **−16,893.54** |
| สัญญาณรบกวน ×100 | 69.68 | 341 | 0.344 | **−16,890.51** |
| `tach` จริง 12.3 Hz | 12.38 | 60 | 0.322 | **10.71** |
| `tach` จริง 36.5 Hz | 36.40 | 178 | 0.198 | **13.01** |
| `tach` จริง 61.4 Hz | 61.48 | 300 | 0.198 | **14.29** |

ค่า 10.7–14.3% ตรงกับที่ `CLAUDE.md` บันทึกไว้ว่าแถบสะท้อนแสงกินมุม
ราว 10% ของเส้นรอบวง ส่วนค่าติดลบ **เป็นไปไม่ได้เชิงฟิสิกส์**

เพิ่มเงื่อนไข `0 < duty_pct < 50` เข้าไปใน `is_trustworthy`

### ทดสอบสองทาง

| ทาง | ผล |
|---|---|
| สัญญาณรบกวนล้วนและ ×100 | `is_trustworthy = False` ✅ |
| ไฟล์ `normal` ทั้ง 49 ไฟล์ | `is_trustworthy = True` **49 / 49** ✅ |
| `validate_tachometer.py` เต็มชุด | ผ่านเกณฑ์ ±1.0% **49 / 49** ไม่เปลี่ยน ✅ |

## ข้อสรุปสำหรับเอกสาร

1. **ระบุหน่วยของ `tach` ว่า "พัลส์ (ใช้เฉพาะจังหวะขอบ)" ได้อย่างปลอดภัย**
   เพราะแอมพลิจูดไม่เข้าสมการ
2. **แต่ `DEFAULT_THRESHOLD = 2.5` ยังผูกกับสเกลของชุดข้อมูลนี้อยู่**
   ซึ่งจะเป็นปัญหาตอนต่อ TCRT5000 ใน Checkpoint 4 เพราะระดับแรงดันต่างกัน
   โค้ดมีโหมด `threshold=None` รองรับอยู่แล้วและให้ผลเท่ากันบนชุดข้อมูลนี้

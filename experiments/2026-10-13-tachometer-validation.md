# ตรวจความถูกต้องของ tachometer → rpm

- วันที่: 2026-10-13
- สคริปต์: `src/data/validate_tachometer.py`
- คลาสที่ใช้ตรวจ: `normal` จำนวน 49 ไฟล์
- วิธี: Schmitt trigger สอง threshold แล้วใช้**มัธยฐาน**ของช่วงห่างระหว่างขอบขาขึ้น

## 1. คุณภาพการตรวจจับพัลส์

- jitter ของช่วงห่างระหว่างพัลส์: มัธยฐาน **0.209%** (สูงสุด 0.383%)
- duty cycle ของพัลส์: มัธยฐาน **13.01%** (ช่วง 10.71–14.29%)
- จำนวนพัลส์ต่อไฟล์: 60–300

jitter ต่ำกว่า 1% ทุกไฟล์แปลว่า**การตรวจจับขอบทำงานถูกต้อง** ไม่มีพัลส์หลอกและไม่มีพัลส์ตกหล่น ถ้านับผิดแม้แต่ขอบเดียว จะมีช่วงห่างยาวสองเท่าโผล่มา แล้ว jitter จะพุ่งทันที


### ความกว้างพัลส์เปลี่ยนตามความเร็วอย่างไร

- duty cycle ไม่คงที่ แต่**เพิ่มตามความเร็ว** (10.71% → 14.29%, สหสัมพันธ์ 0.974)
- ความกว้างเป็นเวลา: 8.65 ms ที่ความเร็วต่ำสุด → 2.32 ms ที่ความเร็วสูงสุด

ถ้าพัลส์เกิดจากแถบสะท้อนแสงที่กินมุมคงที่ ความกว้างต้องแปรผกผันกับความเร็วพอดี แล้ว duty จะคงที่ แต่ของจริงไม่เป็นแบบนั้น ลองฟิต `width_ms = a + b/f` ได้

> **a = 0.797 ms** (ส่วนคงที่ ไม่ขึ้นกับความเร็ว) · **b = 100.1** (ส่วนที่กินมุมคงที่ = 10.0% ของหนึ่งรอบ) · เศษเหลือสูงสุด 0.229 ms

แบบจำลองสองพจน์นี้อธิบายข้อมูลได้เกือบหมด ตีความได้ว่าแถบสะท้อนแสงกินมุมราว 10% ของเส้นรอบวง บวกกับเวลาตอบสนองคงที่ของตัวเซ็นเซอร์และวงจรอีก 0.80 ms **ความสอดคล้องกับฟิสิกส์ขนาดนี้คือหลักฐานว่าการตรวจจับขอบไม่ได้มั่ว**

## 2. เทียบกับชื่อไฟล์

- อัตราส่วน วัดได้/ชื่อไฟล์: **0.99704 – 1.00738** (มัธยฐาน 1.00062)
- ความเร็วที่วัดได้**ต่ำกว่า**ชื่อไฟล์ 0.06% โดยมัธยฐาน
- อยู่ในเกณฑ์ ±1.0% ที่ CLAUDE.md กำหนด: **49 จาก 49 ไฟล์**

✅ ผ่านเกณฑ์ ±1.0% ทุกไฟล์

## 3. มีแนวโน้มตามความเร็วไหม

| ช่วงความเร็ว | ส่วนต่างมัธยฐาน (%) |
|---|---:|
| ต่ำกว่า 25 Hz | 0.44 |
| 25–45 Hz | 0.06 |
| สูงกว่า 45 Hz | 0.02 |

ส่วนต่างเกือบคงที่ทุกช่วงความเร็ว ซึ่งเป็นลายเซ็นของ**ค่าคงที่ที่ใส่ผิด** (เช่น `fs`) มากกว่าจะเป็นความคลาดเคลื่อนของการวัด ถ้าส่วนต่างนี้ยังไม่ใกล้ศูนย์ ให้ตรวจ `fs` ก่อน

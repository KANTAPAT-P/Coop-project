# ตรวจความถูกต้องของ tachometer → rpm

- วันที่: 2026-09-20
- สคริปต์: `src/data/validate_tachometer.py`
- คลาสที่ใช้ตรวจ: `normal` จำนวน 49 ไฟล์
- วิธี: Schmitt trigger สอง threshold แล้วใช้**มัธยฐาน**ของช่วงห่างระหว่างขอบขาขึ้น

## 1. คุณภาพการตรวจจับพัลส์

- jitter ของช่วงห่างระหว่างพัลส์: มัธยฐาน **0.209%** (สูงสุด 0.383%)
- duty cycle ของพัลส์: มัธยฐาน **13.01%** (ช่วง 10.71–14.29%)
- จำนวนพัลส์ต่อไฟล์: 60–300

jitter ต่ำกว่า 1% ทุกไฟล์แปลว่า**การตรวจจับขอบทำงานถูกต้อง** ไม่มีพัลส์หลอกและไม่มีพัลส์ตกหล่น ถ้านับผิดแม้แต่ขอบเดียว จะมีช่วงห่างยาวสองเท่าโผล่มา แล้ว jitter จะพุ่งทันที


### ความกว้างพัลส์เปลี่ยนตามความเร็วอย่างไร

- duty cycle ไม่คงที่ แต่**เพิ่มตามความเร็ว** (10.71% → 14.29%, สหสัมพันธ์ 0.974)
- ความกว้างเป็นเวลา: 8.86 ms ที่ความเร็วต่ำสุด → 2.38 ms ที่ความเร็วสูงสุด

ถ้าพัลส์เกิดจากแถบสะท้อนแสงที่กินมุมคงที่ ความกว้างต้องแปรผกผันกับความเร็วพอดี แล้ว duty จะคงที่ แต่ของจริงไม่เป็นแบบนั้น ลองฟิต `width_ms = a + b/f` ได้

> **a = 0.817 ms** (ส่วนคงที่ ไม่ขึ้นกับความเร็ว) · **b = 100.1** (ส่วนที่กินมุมคงที่ = 10.0% ของหนึ่งรอบ) · เศษเหลือสูงสุด 0.234 ms

แบบจำลองสองพจน์นี้อธิบายข้อมูลได้เกือบหมด ตีความได้ว่าแถบสะท้อนแสงกินมุมราว 10% ของเส้นรอบวง บวกกับเวลาตอบสนองคงที่ของตัวเซ็นเซอร์และวงจรอีก 0.82 ms **ความสอดคล้องกับฟิสิกส์ขนาดนี้คือหลักฐานว่าการตรวจจับขอบไม่ได้มั่ว**

## 2. เทียบกับชื่อไฟล์

- อัตราส่วน วัดได้/ชื่อไฟล์: **0.97367 – 0.98377** (มัธยฐาน 0.97717)
- ความเร็วที่วัดได้**ต่ำกว่า**ชื่อไฟล์ 2.28% โดยมัธยฐาน
- อยู่ในเกณฑ์ ±1.0% ที่ CLAUDE.md กำหนด: **0 จาก 49 ไฟล์**

### ⚠️ ไม่ผ่านเกณฑ์ แต่ไม่ใช่เพราะโค้ดผิด

สองข้อนี้ต้องอ่านคู่กัน

1. jitter ต่ำมาก (0.209%) → การวัด**แม่น**
2. ส่วนต่างเป็นระบบ ทิศทางเดียวกันทุกไฟล์ (-2.63% ถึง -1.62%) → **ไม่ใช่ความคลาดเคลื่อนสุ่ม**

ถ้าโค้ดนับพัลส์ผิด ส่วนต่างจะมั่วทั้งบวกทั้งลบและ jitter จะสูง แต่ที่เห็นคือวัดได้แม่นและต่ำกว่าชื่อไฟล์อย่างสม่ำเสมอ **ข้อสรุปคือชื่อไฟล์ไม่ใช่ความเร็วจริงของเพลา**

สาเหตุที่เป็นไปได้มากที่สุดคือ **slip ของมอเตอร์เหนี่ยวนำ** ชื่อไฟล์คือความถี่ที่ตั้งไว้ที่ไดรฟ์ ส่วนเพลาหมุนช้ากว่านั้นเสมอเมื่อมีโหลด ค่า slip 2–3% อยู่ในพิสัยปกติของมอเตอร์เหนี่ยวนำ (ยังไม่ได้พิสูจน์กลไก แต่ตัวเลขที่วัดได้ยืนยันว่าเป็นระบบ)

**ผลเชิงปฏิบัติ: ต้องใช้ความเร็วจาก tachometer ในการคำนวณความถี่ความเสียหาย ไม่ใช่จากชื่อไฟล์** เพราะ BPFO/BSF/FTF เป็นตัวคูณของความเร็วจริง ถ้าใช้ชื่อไฟล์จะคลาดไป 2% ซึ่งที่ 30 Hz คิดเป็น 2 Hz ที่ตำแหน่ง BPFO เทียบกับความละเอียด FFT 0.2 Hz แล้วคือผิดไป 10 ช่องความถี่

| ต่ำกว่า 25 Hz | -1.92 |
| 25–45 Hz | -2.29 |
